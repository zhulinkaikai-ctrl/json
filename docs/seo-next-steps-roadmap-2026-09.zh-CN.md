# JSONFmt SEO 后续执行路线

更新日期：2026-09-15

English version: [seo-next-steps-roadmap-2026-09.md](./seo-next-steps-roadmap-2026-09.md)

## 目标

在不继续堆积单薄页面的前提下，把现有 Search Console 曝光转化成有效点击和工具使用。JSONFmt 应该逐步成为一个面向开发者、在浏览器本地运行的 JSON 错误诊断与修复中心。

## 当前基线

日期为 2026-09-01 的 Search Console 导出显示约 3,776 次曝光和 2 次点击。大多数曝光来自 20 名之后，因此眼前的主要问题是排名深度和主题权威，而不是页面数量不够。上一轮已经增加静态路由、重点入口、快速修复路径和错误集群内链。

新的观察周期应从最新版本上线并提交 sitemap 后开始。至少积累 7 天新数据前，不要用旧基线判断这一轮页面改动是否有效。

## 前 14 天

1. 部署最新版本，并确认 `/robots.txt` 和 `/sitemap.xml` 返回 `200`。
2. 在 Google Search Console 提交 `https://jsonfmt.org/sitemap.xml`。
3. 为首页、`/tools/`、`/guides/`、主要验证器/错误查找器页面，以及高曝光指南请求重新抓取。
4. 在第 7 天和第 14 天各导出一次 Search Console 数据。
5. 在监控表中记录页面、查询词、曝光、点击、CTR、平均排名和索引状态。
6. 每周最多改 3 个页面。测试标题或内容时保留原 URL。

## 四周执行周期

### 第 1 周：收录和测量

- 确认线上 HTML 有自引用 canonical、一个 H1、有效内链和正确的 sitemap 条目。
- 重点跟踪 `/guides/response-json-is-not-a-function/`，因为它之前的平均排名已经接近首页。
- 同时跟踪 `/guides/unexpected-token-in-json/`、`/guides/json-parse-error/`、`/guides/` 和首页。

### 第 2 周：增强已经获得曝光的页面

- 如果页面有曝光但平均排名在 20 名之后，增强首屏答案、错误/修复示例、排查顺序和正文内链。
- 如果页面进入 8-20 名，测试 title、meta description、H1 和首段表达，让搜索结果承诺更清楚。
- 如果页面进入前 8 名但 CTR 仍低，突出具体错误和修复结果，而不是泛泛描述工具。

### 第 3 周：制作一个外部发现资产

- 发布一篇原创开发者文章，例如 API 返回 HTML 导致 `Unexpected token < in JSON` 的排查过程。
- 文章链接到对应 JSONFmt 指南，并解释真实排查顺序，不要整篇复制站内内容。
- 在相关 GitHub README 或示例仓库中加入 JSONFmt 和有价值的示例数据。

### 第 4 周：根据证据决定方向

- 如果曝光在增长但大多数排名仍在 20 名之后，继续增强旧页面。
- 只有当 Search Console 持续出现某个没有准确对应页面的查询，或真实用户反复报告某种错误时，才新增 1 篇指南。
- 在对应工具真正实现并通过测试前，不要增加宽泛的转换工具页。

## 页面决策规则

| 信号 | 判断 | 动作 |
| --- | --- | --- |
| 已收录、14 天、0 曝光 | Google 尚未发现明确需求或发现信号不足。 | 加强内链，并增加 1 个相关外部发现入口。 |
| 有曝光、平均排名 50+ | 页面匹配弱或权威不足。 | 增加独有排查证据、示例和上下文内链。 |
| 平均排名 20-50 | Google 理解主题，但竞争力还不够。 | 扩展修复流程和相关问题。 |
| 平均排名 8-20、CTR 低 | 页面可见，但搜索结果不够有吸引力。 | 不改 URL，测试标题、描述、H1 和首个答案。 |
| 平均排名 1-8、CTR 低 | 页面已经有点击资格，但承诺不清楚。 | 更明确地写出具体错误和修复结果。 |

## 产品与信任优先级

1. 工具页顶部继续保留可工作的编辑器和诊断入口。
2. 每个已分类错误都链接到对应指南，每篇指南都链接回相关工具。
3. JSON 继续只在浏览器本地处理，绝不把粘贴内容发送到分析系统。
4. 补强 About 和 Privacy 页面，说明维护范围和隐私模型。
5. 在解释相关规则时引用 RFC 8259、MDN `JSON.parse()` 和 Fetch `Response.json()` 等一手资料。

## 现在不要做

- 不购买外链，也不大量提交低质量目录。
- 不通过改 URL 做标题测试。
- 没有实质更新内容时，不要只修改日期。
- 在自然点击和工具使用连续几周稳定前，不要接实时广告。
- 不要用同一套解释只替换关键词，批量生成很多页面。

## 下一次复盘标准

下一次 14 天复盘时，对比新旧数据并回答：

- 收录页面是否增加？
- 重点页面是否向前 20 名移动？
- 哪些具体查询带来最多曝光？
- 哪些页面有曝光但没有点击？
- 用户是否从指南进入验证器或错误查找器？

下一次代码改动应由这些答案决定，而不是只看总曝光数。
