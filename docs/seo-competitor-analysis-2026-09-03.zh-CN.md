# JSONFmt SEO 竞品分析

更新日期：2026-09-03

English version: [seo-competitor-analysis-2026-09-03.md](./seo-competitor-analysis-2026-09-03.md)

## 核心结论

JSONFmt 当前主要不是页面数量问题，而是排名位置问题。日期为 2026-09-01 的 Search Console 导出中，网站约有 3,776 次曝光、2 次点击，观察到的点击率约为 0.05%。约 78% 的曝光来自平均排名 50 名之后的页面，约 96.5% 来自 20 名之后的页面。

因此第一阶段应优先提升已有曝光页面的相关性、主题权威和首屏实用性，而不是继续大量增加单薄的转换工具页。建议定位为：

> 面向开发者的隐私优先 JSON 格式化、验证和错误解决中心。

## 竞品发现

### JSONLint

JSONLint 把验证、格式化、美化、树形查看、文件输入和 JSON 解释内容放在同一个工作流里，用户可以直接粘贴数据并查看错误。

JSONFmt 应学习：

- 编辑器和诊断结果要靠近页面顶部。
- 错误解释应是产品能力，而不只是文章内容。
- 语法指南要把用户带回验证器和格式化器，形成修复闭环。

不应直接复制：

- 对当前修复任务帮助不大的泛化科普内容。
- 在工具没有真实实现前就发布大规模工具目录。

来源：[JSONLint](https://jsonlint.com/)

### jsonformatter.org

jsonformatter.org 是一个大型工具网络。它的 JSON 页面连接格式化、验证、树形查看、文件上传下载、URL 加载、保存分享、JSONPath，以及多个转换和开发者工具分类。这种大量可抓取的链接形成了较强的发现网络。

JSONFmt 应学习：

- `/tools/` 应该成为清晰的工具发现中心。
- 每个重要页面都应该有指向下一步任务的上下文链接。
- 首页应该露出主要工具类别和高价值错误指南。

不应直接复制：

- 尚未实现的几十个转换器路由。
- 与本地处理和隐私定位冲突的保存分享流程。

来源：[Online JSON Formatter](https://jsonformatter.org/)

### jsonfmt.dev

jsonfmt.dev 把格式化、验证、修复、对比、Schema、JSONL、JWT、转换、排序和分析等能力组织成一个客户端工作区，并把浏览器本地处理作为信任信号。

JSONFmt 应学习：

- 第一屏明确产品承诺。
- 用具体模式和任务名称代替泛化动作。
- 把隐私落实成可理解的工作流属性。

不应直接复制：

- 过大的模式面，避免削弱 JSONFmt 最有机会建立优势的严格 JSON 错误诊断。

来源：[jsonfmt.dev](https://jsonfmt.dev/)

## 差距分析

### 1. 排名深度

大部分曝光来自搜索结果很靠后的页面，因此仅修改标题无法解决问题。页面还需要更强的主题连接、更准确的首屏答案和更多可信度信号。

### 2. 搜索意图精度

最有价值的是开发者输入的完整错误消息。围绕完整 parser 错误命名的页面，应该立即回答这个错误，给出最小错误示例、修复示例，并链接到对应工具。

### 3. 内链精度

按错误家族选择相关页面，比所有页面都使用同一组“相关工具”更有用。例如：

- `unexpected token <` 应该链接 JSON Error Finder、JSON Validator 和 Content-Type 指南。
- `single quotes in JSON` 应该链接 JSON Validator、Fix Invalid JSON 和 JSON5 对比指南。
- `JSON parse error` 应该链接 JSON Error Finder、JSON Validator 和 API 响应错误指南。

### 4. 信任与差异化

大型竞品在广度上占优。JSONFmt 应聚焦于：

- 浏览器本地处理；
- 不上传、不要求账号；
- 行号和列号诊断；
- 常见 parser 和 fetch 响应错误解释；
- 从错误消息到有效 JSON 的实际修复路径。

2. 将生成页面的内容日期更新为 2026-09-03。

5. 为核心错误页和工具页增加按意图选择的相关工具、相关指南。
6. 保持所有页面静态、可抓取、有 canonical，并进入 sitemap。

### 下一版本

1. 部署生成后的 `dist`。
2. 对指南中心和前三个高曝光指南请求重新抓取。
3. 每周记录曝光、点击、CTR 和排名。
4. 对排名 8-20 但 CTR 仍低的页面测试标题、H1、描述和首屏答案。
5. 只有在 Search Console 或真实用户错误形成清晰模式后，再增加少量新指南。

### 后续权威建设

- 补充更完整的维护者/关于页面，说明项目范围和隐私模型。
- 链接 RFC 8259、MDN、Fetch API 等一手标准和平台资料。
- 公开诊断规则或错误分类表，让开发者可以引用。
- 通过开发者社区和工具目录获得相关自然链接，不购买链接，也不使用自动化链接方案。

## 衡量规则

不要只看曝光，要结合 Search Console：

- 排名 20 名之后：提升内容深度、内链和权威。
- 排名 8-20：测试标题、H1、描述和首屏答案。
- 排名 8 名以内但 CTR 低：强化搜索结果中的承诺和差异化。
- 连续数周有曝光无点击：把实际查询与可见标题、首段内容逐字对照。

Google 会综合 `<title>`、可见标题、页面文本、锚文本等信号自动生成标题链接。实现时需要让这些信号围绕同一个错误短语保持一致，减少标题被改写成泛化表述的概率。

来源：[影响 Google 搜索中的标题链接](https://developers.google.com/search/docs/appearance/title-link?hl=zh-CN)、[Google SEO 入门指南](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)

## 验收标准

- 分析文档同时存在英文和中文版本。
- 高曝光错误指南在首屏直接回答查询。
- 相关链接按搜索意图选择，而不是只按页面顺序生成。
- 没有为尚未实现的功能增加新路由。
- `npm test`、`npm run lint` 和 `npm run build` 通过。
- sitemap 包含所有生成的公开路由。
- JSON 输入继续只在浏览器本地处理，不发送给分析系统或服务端解析器。
